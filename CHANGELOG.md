# @donotdev/core

## Unreleased

### Breaking Changes

- `buildBreadcrumbJsonLd` (`@donotdev/core`) takes one object and builds the list from the page's ancestor chain: `buildBreadcrumbJsonLd({ pathname, routes, siteName, t, defaultNs, pageUrl, lastName? })` (was `(pathname, siteName, pageUrl, lastName?)`, one item per URL segment). Items: the site, the page's ancestors (`routeAncestors`), each named by its page title (`routeLabel`), then the page (`lastName`, else its route's title). A URL prefix that is no page is no item; no title-cased slug. `EntityPageContext` (`@donotdev/core/next`, `entityRecordSeo`) needs `routes` (the page's route and its ancestors; the generated entity page embeds them as `BREADCRUMB_ROUTES`) and `defaultNamespace`. Migration: pass the object; on an entity page context add `routes` and `defaultNamespace`. Generated Next entity pages are regenerated on the next build. BUGS #35.

- `@donotdev/auth`: the `captchaToken` option and prop are removed (`EmailPasswordFormProps.captchaToken`, `EmailAuthFlowOptions.captchaToken` of `useEmailSignIn` / `useEmailSignUp` / `usePasswordResetRequest`). It only blocked the submit while empty and never reached the provider. The framework now owns CAPTCHA (see Minor Changes); `EmailAuthFlow.blocked` is the client throttle only. Migration: drop the prop and the app's own widget, set `TURNSTILE_SITE_KEY`.
- `@donotdev/ui`: `<Seo>`, `useSeo` and `SeoProps` are removed. Migration: Next entity pages declare their PageMeta `entity` and need nothing more (their head is generated, see Minor Changes); other Next dynamic pages export Next's own `generateMetadata` from a server page module (no `'use client'`), which the generated `page.tsx` re-exports; drop `<Seo>` and its import everywhere (it was the only identity source of Next dynamic pages). `AutoMetaTags` now skips the page identity exactly on the routes listed in `routes.manifest.serverMetadataPaths` (entity pages, blog posts, pages exporting `generateMetadata`); every other route, dynamic ones included, gets its identity from PageMeta + i18n like static pages. Vite dynamic pages keep only that route-level identity: no per-record title, description, image or Product JSON-LD. `buildProductJsonLd` / `deriveEntitySeo` stay exported.
- Route discovery no longer derives the entity from the page's folder (`src/pages/products/` set `meta.entity: 'products'`, a page at the `src/pages` root `'pages'`): folders shape the route path and breadcrumbs only. A page that shows one record by its URL param declares it in PageMeta, as the `defineEntity` definition imported from the app's `entities` package (`PageMeta.entity`, typed `AnyEntity`). The build resolves it statically to the entity's `collection` (`RouteMeta.entity` stays that string for the sitemap, llms.txt, Next prerender, revalidation and server metadata) and fails on a string, an identifier not imported from `'entities'`, an export missing from `entities`, or a value that is not a `defineEntity` call with a literal `collection`. A page without `entity` has no `meta.entity`: it is a plain dynamic page (no sitemap records, no prerendered records, no generated metadata), and navigation groups it by its URL's first segment. Discovery build errors (`createBuildError`, new `isBuildError`) now fail the build instead of being logged with an empty route list. Migration: on each public record page, `import { productEntity } from 'entities';` and add `entity: productEntity` to its `meta`.
- Next entity pages (public single-param route whose page declares its PageMeta `entity`, indexable) answer an unknown or hidden record (no public record with that param value: missing, or `status` in `HIDDEN_STATUSES`) with `notFound()`: HTTP 404 and the app's 404 page, instead of a 200 with the page's own not-found state. The per-request tree reads the same public record, so a signed-in admin opening a hidden record's public URL also gets the 404.
- Next entity pages read their record on the server even with `appConfig.prerenderRecords: false` (which now only skips the build-time prerender). The build fails on such a page when the app has no `entities` package, no site name (`appConfig.app.name` / `seo.siteName`), or a provider without a server reader (`@donotdev/supabase` / `@donotdev/firebase`). Opt out per page: `seo: { noindex: true }`, or a server page module exporting `generateMetadata` plus `prerenderRecords: false`.
- Functions build (`buildFunctions`, `generateFunctionsYaml`): each endpoint of `functions.yaml` binds (`secretEnvironmentVariables`) the secrets its function declares (`secrets: [defineSecret('X')]`), read from the built bundle through the firebase-functions SDK manifest (offline, no secret values). It bound every non-config `functions/.env` key to every function, and nothing once a build had moved them to `.env.local`, so rotated values never reached production and new functions got no secrets. `config.functions[name].secrets` still overrides; a function that declares none binds none. `filterEnvSecrets` moves only declared keys from `.env` to `.env.local` (it never actually rewrote an existing `.env`: the write lacked `overwrite`); other keys stay plain config. New export `detectDeclaredSecrets(functionsDir)`; `generateFunctionsYamlWithInfo` also returns `declaredSecrets`, `autoSecrets` now lists declared names; `envPath` no longer affects secrets.
- Removed the namespace re-exports of `@donotdev/core`: `Types`, `Utils`, `Stores`, `Schemas`, `Hooks`, `I18n`. Import the named symbols instead (`import { createDoNotDevStore } from '@donotdev/core'`, not `Stores.createDoNotDevStore`). The namespace objects kept every module of a package in consumer bundles.
- The browser entry (`@donotdev/core`) no longer re-exports the server-only utils at runtime: `addMonths`, `addYears`, `calculateSubscriptionEndDate`, `parseISODate`, `parseServerCookie`, `validateEnvVar`, `validateMetadata`, `validateUrl` and the `ServerUtils` namespace. Its types never declared them; import them from `@donotdev/core/server`.
- `languageUrls(path, baseUrl, routing, trailingSlash)` (`@donotdev/core`) requires the 4th argument `trailingSlash` (the app's Next `trailingSlash`, `false` on Vite); direct callers must pass it. The generated `sitemap.xml` / `llms.txt` routes call it and are regenerated on build, so apps only rebuild.
- The build fails on a public, indexable `:param` route (not `auth`, not `seo: { noindex: true }`) with no per-URL SEO: no PageMeta `entity` and, on Next, no exported `generateMetadata` (`assertDynamicRouteSeo` in route discovery, both platforms: `[dndev-routes] <file>: public dynamic route <path> has no per-URL SEO ...`, listing the ways out). Such pages served one title and description for every URL. Exempt: error routes, catch-all routes (`/docs/*`, out of the sitemap too) and blog post routes. Migration: declare the page's `entity`, export `generateMetadata` from the server page module (Next), or set `seo: { noindex: true }`.
- PageMeta `entity` written as any expression other than a bare identifier (`import * as entities from 'entities'` + `entity: entities.productEntity`, a call) fails the build ("PageMeta entity `entities.productEntity` is not a bare identifier ... Fix: import { productEntity } from 'entities'; then entity: productEntity"). The meta extractor evaluated it, the evaluation threw, and the page's whole PageMeta was silently dropped (route, auth, namespace, seo).
- A PageMeta the build cannot read fails the build: `[dndev-routes] <file>: PageMeta cannot be read at build: ...`, naming the offending value (`auth: ADMIN_ONLY`: "`ADMIN_ONLY` is not a literal value (an import, a variable or a call)"), the literal-values rule and the fix. `extractMeta` returned `null` instead, silently dropping the page's route override, `auth` guard and `seo`. Migration: write PageMeta values as literals (`auth: { required: true, role: 'admin' }`, not an imported constant); same-file string constants and the `entity` identifier stay allowed.
- Route discovery's route conflict (two pages, one path) and invalid `signedInRedirect` (not an app path, or the page itself) are build errors (`[dndev-routes] <file>: ...`): they were plain errors that discovery logged before returning an empty route list, so the app built with no routes. Theme discovery failing to read the framework token CSS (font defaults) is a build error too (`[dndev-theme] ...`), and the Next discovery orchestrator rethrows build errors from its non-critical handlers (theme, i18n, assets, SEO, PWA, blog) instead of logging them.
- Vite build output: prerendered pages are `dist/<path>.html` (`dist/about.html`, `dist/en/about.html`; the root stays `dist/index.html`), no longer `dist/<path>/index.html`, and the SPA fallback is `dist/_shell.html` (`SPA_SHELL_FILE`, the shell as Vite built it; `dist/index.html` is the prerendered home page). The slash-less URL is served with a 200 and no redirect only with clean URLs. Migration: in your `vercel.json` / `firebase.json`, add `"cleanUrls": true` and point the SPA rewrite at `/_shell` (Vercel: `{ "source": "/(.*)", "destination": "/_shell" }`) or `/_shell.html` (Firebase hosting: `{ "source": "**", "destination": "/_shell.html" }`) (the scaffold templates and `dndev deploy`'s Build Output config, `overrides` + `/_shell` fallback, do this). A config still rewriting to `/index.html` served the home page's tags (canonical included) on every unprerendered URL.

- Fonts have one owner and one way, Next and Vite alike: the **font plan** (`config/fonts/buildFontPlan.js`, new). The theme font tokens name the families (`--font-family`, `--font-headline`, `--font-mono`, every theme), `--font-weight-*` the weights, the app languages the subsets; each family is resolved by name (`appConfig.fonts['<Family>']`, else `@fontsource-variable/<slug>`, else `@fontsource/<slug>` from the app, else the five families `@donotdev/ui` bundles). The framework writes the plan into the server HTML: `<link rel="preload" as="font" type="font/woff2" crossorigin>` for the first paint (body font at `--font-weight-normal`, headline font at `--font-weight-bold`, the page language's subsets) before every stylesheet, and one inline `@font-face` style (`font-display: optional`, `FONT_DISPLAY`; a size-matched `'<Family> Fallback'` face per leading family, now on Vite too). Files: `public/fonts/<stem>.<sha256:8>.woff2`, emptied and rewritten every build (`writeFontPlan`), served `Cache-Control: public, max-age=31536000, immutable` on every target (`headerPolicy.js`, `/fonts/:path*`). Next: `runDiscoveries` builds it before the routes (`routeHandler.useFonts`), writes `src/app/fonts.generated.ts` (`GENERATED_PATHS.next.fonts`), and the generated root layout and global 404 render `<FontHead fonts={FONTS} lang={lang} />` (`@donotdev/ui/next`: React `preload()` + `<style href precedence>`). Vite: `createViteFontPlugin` (replaces `createViteFontPreloadPlugin`, file `vite/plugins/FontPlugin.js`) builds it in `buildStart` (dev: rebuilt on a CSS change), injects the default language's preloads and the style with `transformIndexHtml` (`order: 'pre'`), and the prerender gives each page its language's preloads (`localizeFontPreloads`, `createFontPlanStore`; `createVitePrerenderPlugin` now requires `fontPlan`, `buildPrerenderedPages` takes `pageShell(language)` instead of `shellHtml`). Weights come from the app's tokens: every `--font-weight-*` value a family's source has ships (kbeauty's `--font-weight-semibold: 500` now ships Inter 500). A value the source lacks is no error: the face CSS font matching picks ships (and is the one preloaded), the browser synthesizes as before (no `font-synthesis` rule), and the build logs `🔤 <Family>: weight 700 not in source, browser-synthesized` (`plan.notices`).
  - Build errors (`[dndev-fonts] …`, each with its fix): a family no source provides (generic families and `SYSTEM_FONT_FAMILIES` excepted); a leading family whose `'<Family> Fallback'` is not the next entry of the declaration that writes it (the message prints the line to paste, e.g. `--font-headline: 'Playfair Display', 'Playfair Display Fallback', var(--font-serif);`); a `var()` in a font stack that no CSS defines (a `next/font` class variable); an `appConfig.fonts` file missing or not woff2; `next/font`, an `@fontsource` / `@fontsource-variable` import or an `@font-face` in the app (`src/**`, Vite `index.html`). `dn build` then checks the written HTML (`packages/tooling/src/apps/font-report.ts`) and fails on a page that would flash.

  - Removed: `FONT_FAMILY_TO_STEMS`, `FONT_WEIGHTS`, `FONT_FALLBACK_CATEGORY` (config constants), `config/fonts/resolveFontManifest.js` (`resolveThemeFontFamilies`, `resolveFontManifest`, `catalogueFontStem`, `stripWoffFromSrc`; theme parsing moved to `resolveThemeFonts.js`), `config/next/fonts/copyFontsToPublic.js` (`copyFontsToPublic`, `cleanFontAssets`), `public/dndev-fonts.css` (removed from the app on the next Next build), the `@donotdev/ui/dndev.css` → `dndev-next.css` PostCSS and Turbopack aliases, the `<!-- DNDEV_FONT_PRELOADS -->` marker. `ThemeDiscovery` returns `fontCss` instead of `fontFamilies`. `@donotdev/ui`: `FontPreloadLinks` / `FontPreloadLinksDefault` (`@donotdev/ui/next`) and `@donotdev/ui/dndev-next.css` are removed; `@donotdev/ui/dndev.css` imports no `@fontsource` CSS (the same file on both bundlers).

- The asset manifest (Next: `public/asset-manifest.json` `manifest` and `src/app/assets.generated.ts` `assetManifest`; Vite and Next: `_DNDEV_CONFIG_.assets.mapping`) lists its assets in one array, `assets` (the public path of every scanned asset), instead of `modernFormats` / `fallbackFormats`. ### Minor Changes

- `@donotdev/stores`: `createDoNotDevStore` takes `persistOptions.syncAcrossTabs` (new type `DoNotDevPersistOptions`, both lifecycle modes): when another tab writes the store's persisted key (`storage` event), this tab rehydrates from storage, `_hasHydrated` staying true and no storage write back. Needs `localStorage`-backed storage (the default). Opt-in; nothing changes without it.

- PageMeta `parent` (`'/catalogue'`): the parent page of a page whose URL prefix is no page (`/produits/:slug`, no `/produits` page). Read statically at build (route discovery, Vite and Next) and validated: a literal static path of an existing page (no `:param`, `*`, query or hash; `'/'` = home), not the page itself, no loop (`validatePageParent`, `assertParentChains` in config `RouteDiscovery.js`); a build error otherwise, and when the page's URL prefix is itself a page (that page is the parent). One ancestor chain, `routeAncestors(pathname, routes)` (`@donotdev/core`, config `utils/routeAncestors.js` generated by `bun run bpr`): the direct URL prefix when it is a static route, else `parent`, else the nearest shorter prefix that is one, then the parent's own chain. Its consumers: `@donotdev/ui` `Breadcrumbs`, every BreadcrumbList JSON-LD (`AutoMetaTags`, the Next entity page, the Vite record prerender) and the forms' parent path (`getParentRoutePath`, cancel / after save). Crumbs are named by their page's title, the `<title>` chain (`routeLabel(route, { t, defaultNs, siteName })`: `seo.title`, else `<namespace>:title`, else the full title, else the site name); `breadcrumbNamespaces(pathname, routes)` lists the namespaces those labels read (`Breadcrumbs` and `AutoMetaTags` load them with `useTranslation`). New exports: `routeAncestors`, `getPathPrefixes`, `AncestorRoute`, `routeLabel`, `breadcrumbNamespaces`, `BreadcrumbRoute`. BUGS #35.

- CAPTCHA for Supabase Auth (Cloudflare Turnstile), framework-owned, on when the app sets the public env var `TURNSTILE_SITE_KEY` (`VITE_TURNSTILE_SITE_KEY` / `NEXT_PUBLIC_TURNSTILE_SITE_KEY`); no key = no script, no widget, no token. `@donotdev/core` (`captcha.ts`): `getCaptchaToken()` (a fresh single-use token, `undefined` without a key), `mountCaptchaWidget(container, { language })`, `getCaptchaSiteKey()`, `captchaError()`, `CAPTCHA_FAILED_CODE` (`captcha_failed`), `TURNSTILE_SITE_KEY_ENV`, `TURNSTILE_SCRIPT_URL`, `CAPTCHA_TIMEOUT_MS`. `@donotdev/auth`: `AuthSubmitButton` renders the widget just above the button (every `AuthForm`: `EmailPasswordForm`, `EmailSignUpFlow`, app compositions), `AuthCodeField` above Resend, `EmailLinkForm` above its submit; theme `auto`, the app language, `interaction-only` (a Managed widget shows only when Cloudflare asks the visitor to interact). The script loads with the first widget, never at page load; a gated call with no widget mounted (toast Resend, direct `useAuth` call) gets a one-off widget at the bottom of `<body>`. A CAPTCHA failure is the inline form error `errors.captcha_failed` (13 `auth_*` locales; `isCaptchaError` in the auth rules), also on the password-reset request, which used to hide it. Header policy: `@donotdev/supabase` apps allow `https://challenges.cloudflare.com` in `script-src` and `frame-src` (Vite apps: `vercel.json` headers regenerate on the next dev/build; commit them).
- Icons derived from `public/logo.svg` stay in sync with it and framework defaults never ship (asset discovery, `_generateMissingAssets`, Vite and Next). Outputs: `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192x192.png`, `icon-512x512.png`, `og-image.png`. Missing: generated, as before. Byte-identical to a framework default (`FRAMEWORK_DEFAULT_ICON_SHA256`: every icon the framework ships or has shipped, plus the generator's output from the framework logo): replaced, build warning `replaced framework default public/<file>`. Generated by the framework from an older `logo.svg`: regenerated. Anything else is the app's own: never touched. New committed state file `<appRoot>/.dndev/icons.json` (`ICON_STATE_FILE`: `{ "<file>": { "logo": "<sha256>", "sha256": "<sha256>" } }`, written only when it changes; invalid JSON fails the build). Apps whose `logo.svg` is the framework's (`FRAMEWORK_DEFAULT_LOGO_SHA256`) only get missing icons. Missing `sharp` is now a build warning (`SHARP_MISSING_WARNING`), no longer a debug line; a missing `logo.svg` warning names the framework default icons left in `public/`. Existing icons generated before this change have no record: they count as the app's own until deleted once (then regenerated and recorded).
- Admin user listing: `AuthProvider.listUsers?()` (optional) and `AuthAPI.listUsers` return every auth account as `AuthUserSummary` (`id`, `email`, `emailConfirmedAt`, `createdAt`, `lastSignInAt`, `displayName`; new type, with `ListAuthUsersResponse`). The Supabase and Firebase providers call their admin-only `listAuthUsers` server function (`@donotdev/functions`); `useAuth('listUsers')` throws `UNIMPLEMENTED` on a provider without it. `@donotdev/auth`: new `useAuthUsers()` → `{ users, loading, error, reload }`, loading once auth is ready.
- `DEGRADED_AUTH_API.listUsers` and `.verifyEmailCode` reject with `DoNotDevError('Authentication is unavailable', 'unavailable')` (was a plain `Error` for `verifyEmailCode`).
- Next entity pages get their head from the server, with no app code: the generated `page.tsx` reads the URL's record once per request (React `cache`, shared by `generateMetadata` and the page) with the public reader of `generateStaticParams` (`readEntityPageRecord`), and exports `generateMetadata`: title `<record title> | <site name>` (absolute), description, Open Graph, Twitter card, from `deriveEntitySeo` with the entity's `seo` option and translations in the URL's language (`@donotdev/core/rsc`). PageMeta `seo.type: 'product'` adds Product JSON-LD (`<script type="application/ld+json">`) and `og:type` `product`. Canonical, `og:url` and `hreflang` stay with `AutoMetaTags`. The per-request tree re-exports the same `generateMetadata`. New `@donotdev/core/next` exports: `readEntityPageRecord`, `entityPageSeo`, `jsonLdScript`.
- Next pages may export Next's `generateMetadata` (detected in the page source like `export const meta`, `exportsGenerateMetadata` on the route): the generated `page.tsx` and the per-request tree page re-export it, and it replaces the generated entity metadata on an entity page. A `'use client'` page exporting it fails the build (Next reads it only from server modules).
- The app's Next `trailingSlash` is honored in every public URL: sitemap, llms.txt, canonical, `og:url`, hreflang and JSON-LD end with `/` when `trailingSlash: true` (they used the bare form, so the canonical of `/fr` pointed at Next's redirect to `/fr/`). It reaches runtime through `routes.manifest.trailingSlash` (written by the route generator, read by `AutoMetaTags` and `<Seo>` on server and client) and the generated sitemap / llms.txt routes. New exports `formatTrailingSlash(path, trailingSlash)` (the one place that applies it), `stripTrailingSlash(pathname)` and `languageUrl(path, language, baseUrl, routing, trailingSlash)`. `@donotdev/ui` `useRoutePath` on Next drops the URL's trailing slash, so `/about-us/` still matches the route mapping.
- `@donotdev/ui` `EntityCardList` `pageSize` (`EntityCardListProps.pageSize`, web): opt-in feed rendering. The first `pageSize` cards render (server HTML included), `pageSize` more are added each time the end of the grid nears the viewport, until every card is shown. Data is still fetched in one go; it cuts the cards rendered and hydrated up front, and cards past the first page are not in the server HTML. Omitted: every card renders at once. Ignored by expo.
- Vite entity pages are prerendered per record: with `prerender: 'auto'` (default) the build writes one static HTML per public record of each entity route and per language (`dist/produits/serum.html`, `dist/en/produits/serum.html`), with the record's title, description, canonical, Open Graph / Twitter tags, hreflang, Product and BreadcrumbList JSON-LD, so crawlers and link-preview scrapers get them without JS. Same records and identity as Next: the record lister, sitemap and llms.txt builders moved to `config/utils/` (`publicPages.js`, `sitemap.js`, `llmsTxt.js`), the identity to `config/utils/entityRecordSeo.js` (`entityRecordSeo`, used by Next's `entityPageSeo`; `publicRecordsRoute` in `SEOGenerator.js` is the one route decision). The build reads the database once as a signed-out visitor (`VITE_SUPABASE_URL` / `VITE_SUPABASE_PUBLIC_KEY`, or `VITE_FIREBASE_API_KEY` / `VITE_FIREBASE_PROJECT_ID`; record pages also need `VITE_APP_URL`); a missing variable, a failed read, another provider or no `entities` package fails it. Records published later, values a static route serves and values no file name can hold get the SPA shell. Opt out: `appConfig.prerenderRecords: false` (now honored by Vite).
- Vite `dist/sitemap.xml` and `dist/llms.txt` list the same URL set as Next: written after the bundle with the shared `buildSitemap` / `buildLlmsTxt` over `listPublicPages` (records included, every language URL with its hreflang alternates; one read shared with the record pages). They listed static pages in the default language only (`SEOGenerator.generateSitemap`, `generateStaticLlmsTxt`). Both are deleted, with `SEOGenerator.generateSitemapContent` and the `SEOGenerator` `generateSitemap` option: `generateSEOFiles` writes robots.txt, rss.xml and the SEO manifest, and no longer returns `sitemap`.
- Entity pages carry a BreadcrumbList JSON-LD ending with the record title (`buildBreadcrumbJsonLd` in `@donotdev/core`, built once in `entityRecordSeo`): rendered by the generated Next page (`EntityPageSeo.breadcrumb`) and written into the Vite record pages; `AutoMetaTags` emits no route-label BreadcrumbList there (Next: `routes.manifest.recordBreadcrumbPaths`; Vite: the embedded head). `@donotdev/ui` `useRecordBreadcrumb` labels the URL segment naming the record (the route param filled by the record field of the same name, e.g. the slug, else the id), so the visible breadcrumb shows the same title on slug URLs; it kept the slug.
- `@donotdev/core` head builders shared by `AutoMetaTags` and the Vite prerender (`headTags.ts`): `routeSeo`, `routeTitle` (the title chain alone: `<title>` and the page's own title), `routeHeadTags`, `recordHeadTags`, `siteHeadTags`, `buildBreadcrumbJsonLd`, `robotsContent`, `readI18nSeoMeta`, `resolveSeoField` (moved from `@donotdev/ui` internals), `jsonScriptText`, `PRERENDERED_HEAD_ELEMENT_ID`, types `HeadTag`, `RecordSeo`, `RouteSeo`, `PrerenderedHead`.

### Patch Changes

- `@donotdev/ui` / `@donotdev/core`: the `WebSite` JSON-LD no longer carries `potentialAction` (`SearchAction`, sitelinks search box): Google retired it on 2024-11-21, and it pointed at `/search` even on apps with no search page. The `WebSite` block (name, url) stays; `seo.websiteSchema` still toggles it.

- `@donotdev/ui` Breadcrumbs and the BreadcrumbList JSON-LD no longer name or link URL prefixes that are no page: `/produits/serum` read Home > Produits (the slug title-cased; the JSON-LD linked `/produits`, a 404) > product. The trail is the ancestor chain (see PageMeta `parent`), each crumb named by its page title; the page itself by its route's title (the record's name once `useRecordBreadcrumb` sets it, as before). `Breadcrumbs` and the forms' parent path read the build's route manifest (`getRoutes`, as `AutoMetaTags`), no longer the auth-filtered navigation routes: the server HTML and the browser build the same trail. BUGS #35.

- `@donotdev/ui` Breadcrumbs: the trail wraps instead of overflowing (long record names on a phone), and only the layout's breadcrumb bar (`.breadcrumbs-container`) insets it; a `<Breadcrumbs>` placed in page content is flush with the content edge (it sat `--gap-sm` to the right of the text it heads).
- `@donotdev/ui`: a Next page's `notFound()` (generated entity pages on a missing record, or a page's own call) shows the app's 404 page; `redirect()` from a client page redirects (BUGS #32). The framework error boundary (app and `PageContainer` levels) caught Next's router control flow and showed "Something went wrong" (the HTTP status was already 404). - One HTTP response header policy (`config/headerPolicy.js`): security headers, CSP built from directives plus the backend provider's sources, `X-Robots-Tag: noindex` for `seo: false`, cache classes. `script-src` baseline per target: `'self'` on Vite (builds have no inline scripts), `'self' 'unsafe-inline'` on Next (inline bootstrap scripts); `appConfig.headers.csp` accepts hash sources (`'sha256-<base64>'`) for a Vite inline script, and malformed quoted sources fail the build. Apps declare deltas in `appConfig.headers` (`csp` sources, per-path `cache` overrides). Next serves it from `headers()` in production builds and fails the build when the app's `vercel.json` has `headers`; Vite (and Next `output: 'export'`) writes it into the `headers` key of the app's `vercel.json` at dev/build start, and fails on CI when the committed file is stale. Scaffolded `vercel.json` files carry no header rules; `csp.example.json` is gone.
- `defineNextConfig` passes the app's own Next options through (the documented contract): they were silently dropped because the Next config function's `phase` argument shadowed them. `webpack`, `rewrites`, `redirects` and `headers` are composed with the framework's (app `headers` after the policy).
- App URL (`AppConfigProvider`) resolves from the `APP_URL` env var on server and client alike (dev without it: `http://localhost:3000`). Dev used `window.location.origin` in the browser and `localhost:3000` on the server, so SSR on another port hydrated with a JSON-LD/canonical mismatch.

Any other icon name string (`<Icon icon="Rocket">`, `Link icon`, auth menu items) loads through `lucide-react/dynamic`, one async chunk per icon, with a same-size placeholder until it arrives (none in server HTML). - `@donotdev/ui` `Link` on Next.js renders `next/link` for internal paths, so routes are prefetched (next/link default; `prefetch={false}` disables it) and navigation is client-side through Next. `prefetch` was accepted but never applied (a plain `<a>` + `router.push`). Same public API and a real `<a href>` in the current language; overlays still close on navigation; on Next an `onClick` calling `preventDefault()` now cancels the navigation (next/link). Vite keeps react-router navigation. The platform link is the new `@donotdev/ui/routing/link` subpath (`vite-app` condition → Vite, default → Next, like `routing/hooks`). Cards (`href`) and Tables link through it.

The logo no longer reads `modernFormats`. Discovery still never generates or copies a `logo.*`; delete a stale `public/logo.png` the app does not use.
